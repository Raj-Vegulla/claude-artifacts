Biggest Finding — Abandoned Listings

The 39K Listing Problem

Correctly Syncing
3,838

Affected

The CMS ↔ DataLake weekly audit surfaced the largest-scale data integrity issue currently being tracked. These are "abandoned listings" that fall into two distinct root causes.

Lower Severity

Category 1: Inactive Agent, Unarchived Listings

Agent no longer active (left brokerage, license expired), but their listings were never cleaned up from CMS. These are orphaned records — they sit on the client's website but cause no active harm. They need to be archived.

High Severity

Category 2: Agent ID Drift from MLS Migrations

During MLS migrations, agent IDs changed but CMS was not updated. Result: MLS sync is on, but no updates are flowing. The agent believes their listings are syncing — they are not. This is a silent failure that was generating support tickets.

🛤️
Remediation Status

Abandoned Listings — Path Forward

Why this matters

Category 2 listings create a silent failure — the client and agent believe sync is working, but listing updates are not flowing. This erodes trust and generates avoidable support tickets like "my listing is not updated."

What we have today

A manual archival tool already exists. The DCT and Data teams use it today — they check the authorization report, confirm the agent is inactive/junk, and archive the listing. This is working, but it does not scale to ~39,000 listings.
